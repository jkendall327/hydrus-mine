# Conventions for hydrus-rs code

Read `ARCHITECTURE.md` first. These are the rules every crate follows.

## Design

- **Types over conventions.** Use the id newtypes (`HashId`, `TagId`, ...),
  `Sha256`, `Mime`, `ServiceKey`, `Tag` from `hydrus-core`. Raw integers and
  byte vectors only at I/O boundaries.
- **Make illegal states unrepresentable.** Prefer enums with data over flags
  plus optional fields. Parse, don't validate: convert untrusted input into
  typed values at the edge (HTTP handler, legacy reader), then trust them.
- **The reference implementation is a spec, not a template.** Port behaviour,
  not structure. Don't reproduce Python class hierarchies, stringly-typed
  dispatch, or version-upgrade chains. If the reference behaviour is clearly a
  bug that users would not rely on, don't copy it; write down the difference in
  `docs/rust/DIFFERENCES.md`.
- **No global mutable state.** State is owned by a struct and passed explicitly.
- **Concurrency**: share immutable snapshots (`Arc`), send messages to owners
  of mutable state. Don't hold locks across I/O or `.await`.

## Errors

- Libraries define error enums with `thiserror`. Binaries and tests may use
  `anyhow`.
- No `unwrap()`/`expect()` on anything that depends on input or I/O. They are
  fine for true invariants (with an `expect` message saying why it holds) and
  in tests.
- No `unsafe`. The workspace denies it.

## Tests

- Every behaviour ported from the reference implementation gets a test that
  checks it against reference output, either a fixture in `oracle/fixtures/`
  (generated by a script in `oracle/`, committed along with the script) or a
  conformance recording.
- Use `proptest` for anything with an algebraic property (round trips,
  idempotence, incremental == rebuild).
- Tests must not need Python or the network. Fixture generation may.

## Style

- `cargo fmt`, and `cargo clippy --all-targets -- -D warnings` with the
  workspace's pedantic lint set, must be clean.
- Doc comments on every public item say *what it is for*, not what the code
  literally does. Module docs explain the design of the module.
- Keep functions small enough to read; keep modules cohesive.

## Parity

- When you implement something listed in `parity/manifest.toml`, flip its
  status in the same change and run `cargo xtask ratchet --update`.
