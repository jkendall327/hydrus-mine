# Selected thumbnail maintenance repair (unapplied)

`selected-maintenance.patch` modifies four files and avoids GUI/lib hot spots. Reference: `hydrus/client/gui/pages/ClientGUIMediaResultsPanel.py:1297-1311` captures selected flat media and gives those results to `RunJobImmediately`; `hydrus/client/files/ClientFilesMaintenanceManager.py:1504-1552` constructs a selected-media-to-single-job map and runs it under its lock. Scheduling later is separately sent to the global queue. Native `crates/hydrus-gui/src/thumbnail_maintenance_window.rs:63-68` instead queued selected IDs, then called a global type-only runner with selection length as its limit. `crates/hydrus-store/src/file_maintenance.rs:323-324` fetched arbitrary due IDs before LIMIT 256. A queued unrelated file could consume the immediate budget and receive maintenance, including record-removal jobs, while the selected file waited.

The proposed store `due_jobs_of_files` applies `hash_id IN rarray(?3)` in SQL before LIMIT 256 and retains the existing due threshold, job-type/run ordering and multi-job grouping. Empty selections admit nothing; duplicate IDs use membership rather than a join. Existing global callers retain the original SQL. The importer reuses the same inner runner with optional selected IDs, so crash-safe physical-work lease, ordinary contention deferral, forced cancellation while waiting/between files, callbacks, limits, weights, ownership policy and per-file commit behavior stay centralized. The thumbnail caller clones the captured IDs before moving them into the queue-write closure, then passes the selection to the importer. Already-admitted refresh callback/timer and thumbnail prompt ownership are outside this repair.

Authored regressions cover SQL admission behind >256 unselected jobs, 300 unselected Store media records plus 270 selected records across multiple batches, real selected PDF transparency-flag repair with unselected flags unchanged, exactly preserved queue rows for unselected/unwanted/future jobs, empty and duplicate selections, reopening persistence, lease contention, pre-cancelled forced work, cancellation after one durable file commit, and weight budget. The large backlog records are synthetic valid hashes/media rows with deliberately stale PDF flags; this metadata job needs no physical bytes or external tools. This is real Store/importer behavior rather than a stubbed queue. Physical destructive-job/reference-recording replay and actual native GUI menu/render proof remain pending; the patch does not grant completion credit.
